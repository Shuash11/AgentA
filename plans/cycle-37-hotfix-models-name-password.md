### 2.1 Defect 1 — the decline copy maps to HTTP 403, not to a masked generic

Code-path deduction (all read today):

- The ONLY raw error that yields "The AI service declined this request. Try rephrasing or switch models." is one containing `declined` or `rejected the request` (`chat_error_classifier.dart:99-100`). The generic catch-all (`:74-78`) and every other OpenRouter row produce different copy.
- The only service message containing `rejected the request` is `_msgForbidden = 'OpenRouter rejected the request (403).'` (`openrouter_service.dart:221`), thrown by `_serviceMessageForStatus` for status 403 (`:237-238`) — or by a mid-stream SSE error event carrying code 403 (`:252-264`, `:435-439`).
- Therefore the shipped build **received 403** (pre-stream HTTP status or mid-stream event). Candidate causes 401-invalid-key, 402-quota, 429-rate-limit, and empty-key are **ruled out** — each maps to different copy the user did not see (`openrouter_service.dart:233-246`; `chat_error_classifier.dart:62-70`).
- The service discards the error BODY entirely: `_serviceMessageForStatus(int statusCode)` reads only the status (`openrouter_service.dart:231-247`). OpenRouter's 403 body carries the actual cause in `error.message` + `error.metadata` (live docs, fetched 2026-10-28): **budget/key-limit exhaustion also rejects with 403** (`error.metadata.limit_source` ∈ `openrouter_guardrail_budget` / `openrouter_workspace_budget` / `openrouter_key_limit`), as do guardrail blocks and moderation (`error_type` ∈ `permission_denied` / `content_policy_violation` / `refusal`). `GET /api/v1/key` exposes `budgets` / `effective_budget` before they block.
- **Leading hypothesis:** cycle-36 §4.2 advised the user to create the rotated key "optionally with a credit limit cap". A key-limit-capped (esp. $0-capped) key returns 403 on every request — matching a decline on trivial input. Alternative 403 causes: guardrail/moderation false-positive, insufficient permission, region block. The probe (§4.1) settles it from the raw body.
- Also recorded (live docs): a non-stream `200` response may carry ONLY an `error` object with no `choices` (provider error after headers). The app's non-stream path parses that as `content:null` → throws `'OpenRouter request error: invalid response body'` (`openrouter_service.dart:330-332`) → classifier maps to "failed to respond" (`chat_error_classifier.dart:105-106`) — cause-honest only by accident; covered by the conditional contract amendment (§6-P2).
