## Findings backlog (Level 2 — the single finding being fixed)

**Finding (the core defect): the offline model has no working conversational memory.**
Live device evidence (v1.9.2, OPPO CPH2591, verbatim): "my name is tester" → "what is my name" returns the identical canned greeting in two independent fresh chats; polluted chats collapse into canned `Hola!` repeats and 2,300–2,800-char loops; fresh chats answer cleanly.

Root cause ruled from first-hand reads at HEAD `5fda352` + pinned pub-cache sources (evidence table below). The history assembly is correct app-side; the delivery mechanism destroys turn structure at the engine boundary:

1. App side: every send calls `chat.clearHistory()` — full session wipe (`flutter_edge_ai-1.11.4 lib/core/chat.dart:966-973`) — then re-stages the capped window as chunks (`lib/services/ai/gemma_service.dart:511-516`).
2. Plugin side, `.task` assets: `_chatFormatMode.raw` strips every role marker — an assistant message transforms to its bare text, indistinguishable from user text (`flutter_edge_ai-1.11.4 lib/core/extensions.dart`, `_chatFormatModeFor`: `fileType == ModelFileType.task → raw`; `_formatToolResponseContent` returns plain `text`).
3. Plugin side, session: every staged chunk only accumulates into one buffer; `getResponse` issues ONE generation over the whole buffer (`flutter_edge_ai_litertlm-1.8.6 lib/src/ffi/ffi_inference_model.dart:408-414, 483-486`; `flutter_edge_ai_mediapipe-1.0.8 lib/src/mobile/mobile_inference_session.dart:75-112, 132-140`).

Net effect: prior user turns + prior assistant turns + the new message reach Qwen2.5-1.5B as ONE role-less user string. A 1.5B pattern-completes it to the greeting (the identical-greeting memory failure) and parrots/loops on polluted buffers. Fresh chats stage nothing — one clean turn — matching the scorecard exactly.

Secondary trigger: the plugin's session-rotation (`_currentTokens >= maxTokens - tokenBuffer`, threshold 1792 with the app's unpinned defaults: `maxTokens 2048` at `gemma_service.dart:67`, `tokenBuffer 256` default at `ffi_inference_model.dart:260`) replays `_modelHistory` — user AND assistant messages — as chunks before one generate (`chat.dart:717, 938-964`): the same role-collapse on long chats even without the app's per-send wipe.

Non-goals (recorded, not fix targets this cycle): multi-step math weakness (`0.15 * 80 = 11`) = the recorded 1.5B class ceiling; binary/unit conversion failures = same class. The math-specialist tier (DeepSeek distill, cycle-42 §1.3(a)) remains the recorded future answer; the 0.5B rung stays armed for RAM kills.

- **S1 — RULED: the per-send wipe STAYS; priming is PER-SEND unconditional.** Phase-1 item 1's wording ("the engine accumulates the alternating context natively") is WITHDRAWN — it depended on native response-retention, which is unverified from Dart (the plugin never re-stages the assistant turn: `chat.dart:186` stages only the current message; :189-195 is bookkeeping-only) and contradicted this plan's recorded Assumption.
