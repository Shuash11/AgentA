## ROOT CAUSE (P1 diagnosis; independently reproduced by the Adviser 2026-10-16)

**The repo `Shuash11/AgentA` is PRIVATE, and the app's update check sends NO credentials.**

Adviser reproduction (this session): anonymous `curl` → repo `404`, `releases/latest` `404`; control `repos/flutter/flutter` → `200`; authenticated `gh api` → `{"private": true, "visibility": "private"}`.

**Causation chain (fully traced):** boot → `_startMainApp` post-frame → `init()` (release gate passes) → fetch → **404** → `return null` (`github_releases_source.dart:65-68`, commented as a "valid nothing-to-see") → `version_check_service.dart:229-235` emits nothing, no state change → the host never sees a showable state → **no dialog, ever**. Release builds additionally strip every `kDebugMode` log (`:201-203`, `:310-312`) → **zero field observability** — which is why the defect shipped and survived a release cycle. The design premise at `app_config.dart:34-37` ("Public URL (repo is public)") is **factually wrong**.

## CORRECTED ground truth (evidence audit — recorded for the trail)

- **CORRECTED:** the earlier claim "GitHub releases are published and `/releases/latest` returns v1.2.5, so the endpoint works **unauthenticated**" was **WRONG**. The `gh` CLI auto-attaches the logged-in token, so authenticated success was mis-recorded as anonymous success — by the Orchestrator's evidence-gathering and repeated as "verified" in this plan's earlier ground-truth row by the Adviser. **Lesson recorded: anonymous behavior must be tested anonymously.** What remains true from that evidence: tags `v1.0.0…v1.2.5` exist; the feature is in the `v1.2.4` tag (`git ls-tree`; pubspec `1.2.4+1`; introduced in `a371ccd`); wiring is present; dismissal is written only post-dialog-close.
- **Reproduction:** installed CI-signed `com.agenta.AgentA` 1.2.4 + any newer published release → dialog expected → **absent** (because the check 404s anonymously).

## Suspect verdicts (all six, P1)

1. **Silent-failure design — CONFIRMED (as a design defect, not the network):** **10 silent return paths** (source: 404 `:65-68`, 403/429 `:69-72`, other status `:73-75`, catch `:77-81`, bad JSON `:126-129`, non-map `:130`, draft/prerelease `:134-137`, bad tag `:139-146`; service: null-no-emit `:229-235`, catch `:249-252`). 10/10 produce no state, no stream event, no UI; release builds emit zero logs. A failed check is indistinguishable from "up to date" on-device. (The NETWORK was never the problem — the auth wall was.)
2. **Release-build gate — RULED OUT as cause:** CI builds `--release` (`build-apk.yml:305`), so checks run. Caveat adopted into the fix: a debug/profile install silently disables all checks — the manual row must surface `skipped(nonRelease)`.
3. **Boot-path reachability — RULED OUT:** every usable path reaches `init()` (backend-failure catch has no return; `_continueOffline` sets `databaseReady`); the only skip is DB-init failure → unusable-app screen (low plausibility).
4. **Persisted dismissal — RULED OUT:** sole writer is `dismissUntilNextVersion` (`update_cubit.dart:180`), called only by the host post-close handler; suppression requires a dialog that was already shown.
5. **Version source + semver — RULED OUT:** scratch proof (temp only, never committed), 15/15 PASS incl. `decide(1.2.4 vs real v1.2.5 payload)` → **available**; `+1` build excluded; `v`-strip correct. The logic is correct — it just never runs against a successful fetch.
6. **Timing/readiness — RULED OUT:** host mounts post-`runApp`; check starts post-frame; cubit seeds + buffers. Minor hardening adopted: the host's `navigator == null` early-return gets a post-frame retry (P4).

## THE UPDATE CHANNEL (blocking workstream — the root-cause fix)

- **(A) Make the repo public** — the design's original intent; **zero code changes**; matches `app_config.dart`. **Gated on the mandatory pre-flip secret-history audit (P2).** The flip is a USER action (owner-only, security-relevant).
- **(B) A separate PUBLIC releases-mirror repo** that CI publishes to — source stays private; requires a cross-repo fine-grained PAT (`contents:write` on the mirror only) as an Actions secret + workflow target changes + `app_config` URL change.
- **REJECTED: shipping a token in the APK** — APK-extractable; GitHub docs explicitly forbid client secrets in client-side code (P1-cited).
- **Without (A) or (B), the dialog cannot work — this is the root-cause fix.** P3–P5 are the hardening that makes failures observable and prevents recurrence.
