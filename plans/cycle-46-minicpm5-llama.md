### 2.4 The thinking mechanics — the branch ruling (fluttergemma.dev + vendor card, 2026-11-02)

- **The switch is the template's `enable_thinking` kwarg.** The GGUF's embedded template: `enable_thinking: true` → generation prefill opens a bare think block (the model opens its thought); `enable_thinking: false` → pre-fills an EMPTY think block (thinking-off is the template's structural off-switch); **`enable_thinking` UNDEFINED → NO prefill — the model decides** (a deep-thinking-SFT model may think by default). The vendor card's own usage passes `enable_thinking=True` explicitly (Transformers example). **Therefore the app must pass `enableThinking` EXPLICITLY on every chat creation — never rely on a default.**
- **THE BRANCH (the plan's #1 risk):** core parses think tags into `ThinkingResponse` **only for `ModelType.deepSeek`, `qwen`, `qwen3`, `qwen35`** — "`general`, `phi` **and the others have none**" (`/docs/thinking-mode`, verbatim; `llama` is one of "the others"). - **The loop guard has a VENDOR-PRESCRIBED anchor (llama.cpp-specific, vendor card, verbatim): "In llama.cpp, the default `min_p=0.05` can lead to repetitive output: it filters out tokens whose probability is below 5% of the highest-probability token, potentially discarding the exact tokens needed to break out of a repetition loop. To prevent this, we set `min_p=0.0`."** — recommended sampling: `temperature: 1.0, top_p: 0.95, min_p: 0.0`.
