# OOP Modularized

Keep code object-oriented where useful, modular, simple, and readable by humans. Goal: maintainable code another developer can understand quickly.

## Rules

- Use OOP when classes/objects clearly improve organization, reuse, or maintainability.
- Do not force OOP where simple functions or structures are clearer.
- Divide code into small modules with one clear responsibility.
- Avoid large files, god classes, deeply nested logic, and unnecessary abstractions.
- Prefer simple composition over complicated inheritance.
- Keep functions and classes focused and easy to understand.
- Reuse existing project patterns instead of introducing a new architecture unnecessarily.
- Use clear, descriptive names.
- Keep logic explicit and readable; avoid clever or overly compressed code.
- Do not create abstractions for code that does not need them.
- Keep dependencies between modules minimal and clear.
- Follow the project's existing architecture unless there is a strong reason to improve it.
